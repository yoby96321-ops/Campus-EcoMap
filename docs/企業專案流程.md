# Campus EcoMap 企業專案流程與交接

版本 v1.0.0。範圍為三民校區至一中商圈、50 筆公開資料、兩筆課堂示範、四種交通。專題目標是協助學生在一次操作中核對設施與比較往返交通碳排。課堂版以零外部前端依賴與可離線重現為交付條件。

## 生命週期與關卡

| 階段 | 工作與產出 | 關卡與責任 |
|---|---|---|
| 立項與探索 | 確認學生查找需求、使用場景、SDG 13、範圍與主要風險 | 組長確認功能邊界，課程提案為原始依據 |
| 需求與規劃 | 建立下表追蹤、交付項目、角色、驗收情境 | 組長評估影響與任務順序，資料負責人同步準備來源 |
| 設計 | 資料模型、響應式圖卡、狀態、瀏覽器相容性、隱私與無障礙 | UI 與互動負責人檢查鍵盤、空結果及小螢幕 |
| 實作與審查 | HTML/CSS/JS、資料校驗、版本控制、CI、測試案例 | 合併前由另一團隊成員審閱變更，核對來源與影像標示 |
| 驗證與驗收 | 單元測試、瀏覽器測試、離線演練、課堂驗收腳本 | 自動化檢查已有執行證據。課程方與團隊簽核待實際驗收 |
| 發布與交接 | 靜態建置、版本標記、保留 ZIP、環境冒煙測試、回滾計畫 | 組長管理版本。公開發布門檻包含店家訪查與資料審核 |
| 營運與迭代 | 監控連結與異常、修復回歸、更新資料、保留舊版本 | 資料負責人複查，互動負責人驗證，組長核准發布 |
| 結案 | 移交來源、驗收證據、素材登錄、已知限制和後續議題 | 組長彙整驗收日期及核准人，確認持有原始碼與發布權限 |

原報告分工保留為責任規劃。梁宸翰負責首頁與 CSS，陳欣沅負責店家資料與設施，阮仲達負責估算與整合測試。實際人員審核、訪查、教師評分及簽核依現場紀錄填寫。

## 資料治理與變更控制

公開店家紀錄包含固定 ID、顯示名稱、分類、單程示範距離、來源 URL、查核狀態。設施使用 true（有）、false（無）或缺值（待確認）。地址、價格與門市現況逐欄以店家公告或實訪查證，保存來源、查證日期、查核人與證據。若店家搬遷或停業，先停用對應紀錄，更新來源及導航後重跑相關測試。示範店家及示範距離不得移入實測欄。

變更以議題記錄問題、重現情境、影響、負責人與驗收條件；透過分支與 PR 提交，保留審查與 CI 結果。新的排放係數需記錄來源、適用地區、年份與邊界，重新計算基準答案並更新方法說明。資料待查優先依重要度排入待辦，包含各店價位、座位、冷氣、Wi-Fi、插座、可使用照片和實際路線距離。

## 風險與營運

| 風險 | 處置 | 負責角色 |
|---|---|---|
| 店家、設施與價位過期 | 逐欄標示證據狀態；發布前及每學期重看資料 | 資料 |
| 距離或係數被誤讀 | 圖卡、詳情、結果及方法都標明示範，未經實測不標成店家碳排 | 互動 |
| 影像授權與誤認 | 本版用生成餐點示意；上傳新照片需記錄拍攝或授權來源 | 資料 |
| 展示現場網路失效 | 直接開啟本機 index；外連失敗時說明其依賴，繼續核心展示 | 組長 |
| 瀏覽器或發布故障 | 檢查 HTTP、JS/CSS 和圖片後重跑冒煙測試，必要時回滾 | 互動 |

每次發布保存版號、Git commit、測試結果和上一版靜態檔。發布後檢查首頁、圖卡、詳情、導航 URL、碳排公式及手機版。收到回報後先重現並分級，無法開啟或算式錯誤優先處理，普通資料錯誤更新來源後再發布。無法即時修復時回滾上一版並記錄事件，重跑驗收後才恢復。專案下架前匯出版本與證據，撤下站點並在課程交付資料中保存可離線版本。

建議課堂驗收留下日期、環境、案例結果、阻斷問題及驗收人。任何實地調查或測試受試者數量都以實際證據登錄。
